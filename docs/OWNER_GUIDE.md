# دليل مالك «العيسائي برو»

> مرجع واحد للتحكم بالتطبيق والمستودع. **لا تكتب في هذا الملف رمز GitHub ولا كلمة المرور ولا عبارة التشفير** — المستودع عام، وأي شيء فيه يراه الجميع.
> الإصدار الموثَّق: 2.6.0

## 0) أين أحفظ هذا الملف؟
- **في المستودع:** في المجلد `docs/` باسم `docs/OWNER_GUIDE.md`. هذا المجلد لا يقرؤه التطبيق ولا الاختبارات ولا سير النشر، فلا يسبب تعارضاً ولا تعطيلاً. (إن كان موقعك منشوراً من الفرع مباشرة سيكون الملف مرئياً بالرابط العام، وهذا مقبول لأنه بلا أسرار.)
- **على هاتفك:** انسخه أيضاً. الأسرار (الرمز وكلمة المرور وعبارة التشفير) لا تحفظها في المستودع؛ احفظها في مدير كلمات مرور أو ورقة خاصة بك.
- لا تضعه في: `addons/` (سيُقرأ كإضافة)، ولا `src/`، ولا `catalog/` (يُولَّد تلقائياً ويُمسح).

## 1) خريطة المشروع: ماذا يفعل كل شيء وهل ألمسه؟
| المسار | وظيفته | هل أعدّله؟ |
|---|---|---|
| `index.html` | هيكل الصفحة والـSEO | نادراً (النصوص والروابط فقط) |
| `assets/css/app.css` | التصميم (داكن/فاتح) | نعم للتصميم |
| `assets/images`, `fonts`, `screenshots` | الأيقونات والخطوط واللقطات | عند تغيير الشعار فقط |
| `src/*.js` | كود التطبيق | لا، إلا بتطوير مقصود (انظر §9) |
| `src/version.js` | رقم الإصدار و«ما الجديد» | **نعم عند كل إصدار** |
| `sw.js` | العمل دون اتصال والتحديث | رقم `VERSION` فقط عند كل إصدار |
| `manifest.json` | بيانات التثبيت كتطبيق | عند تغيير الاسم/الألوان |
| `addons/<اسم>/` | إضافات المستودع | **نعم: هنا تضيف وتحذف إضافاتك** |
| `catalog/src/` | (اختياري) مصادر إضافات أخرى؛ النظام لا يشحن إضافات جاهزة | نادراً |
| `catalog/index.json`, `catalog/addons/` | الكتالوج المبني | **لا يدوياً**: يُولَّد بـ`node tools/build-catalog.mjs` |
| `privacy.html`, `terms.html` | الخصوصية والشروط | عند تغيير سياستك |
| `store/`, `STORE_GUIDE.md` | ملفات النشر في المتاجر | عند النشر في متجر |
| `tests/`, `tools/`, `.github/` | الاختبارات والأدوات والنشر الآلي | لا |
| `docs/` | هذا الدليل | نعم |

## 2) نشر تحديث (الروتين الأهم)
1. عدّل ما تريد.
2. **ارفع رقم الإصدار في ثلاثة أماكن معاً** (يفشل الاختبار إن اختلفت): `src/version.js` (`APP_VERSION` وسجل التغييرات `APP_CHANGELOG`)، و`sw.js` (`VERSION`)، و`package.json` (`version`). اكتب سطراً في `CHANGELOG.md`.
3. ارفع إلى فرع `main`. يعمل سير العمل `pages.yml`: يبني الكتالوج، ويشغّل اختبارات الوحدة، ويختم رقم البناء، وينشر.
4. يصل التحديث لكل من يفتح التطبيق: يكتشف Service Worker النسخة الجديدة ويعرض إشعار «يتوفر إصدار جديد».
5. تحقق: افتح الموقع، وفي ⚙️ ← النظام ← «حول التطبيق وما الجديد» (رقم الإصدار)، وتبويب Actions في GitHub (علامة ✅).

> **شرط:** من Settings ← Pages ← Source اختر **GitHub Actions**. إن كان المصدر «Deploy from a branch» فلن يُبنى الكتالوج تلقائياً؛ شغّل `node tools/build-catalog.mjs` على جهازك وارفع `catalog/` معه.

## 3) الإضافات: إضافة وتعديل وحذف
### صيغة الإضافة
مجلد داخل `addons/` **باسم من اختيارك بأي لغة** (عربي أو إنجليزي أو بمسافات، حتى 60 حرفاً؛ الممنوع فقط `/ \ : * ? " < > |` ونقطة في أول الاسم أو آخره):
```
addons/اسم-الإضافة/
  manifest.json   (إلزامي)  {"id":"اسم-الإضافة","name":"الاسم الظاهر","icon":"🧩","version":"1.0.0","description":"...","author":"..."}
  index.html      المحتوى
  main.js         الكود (اختياري)
  style.css       الأنماط (اختياري)
```
المجلدات المتداخلة مسموحة حتى 8 مستويات، مثل `src/bridge/AisaiAdapter.js`. اربط ملفاتك بمساراتها داخل `index.html` (`<script src="src/bridge/AisaiAdapter.js"></script>` و`<link rel="stylesheet" href="css/app.css">`) أو اذكرها في `manifest.json` ضمن `scripts` و`styles` بالترتيب. ومن الكود: `Alaisai.file("data/config.json")` تقرأ أي ملف نصي من الإضافة، و`Alaisai.files()` تعدّدها.
القيود: 300 ملف كحد أقصى، نحو 3MB للملف (النص حتى 500 ألف حرف يبقى قابلاً للتحرير، وما فوقه يُحفظ ثنائياً)، ونحو 10MB للإضافة كلها. تعمل في إطار معزول، وتتحدث مع النظام عبر `Alaisai`: `toast / get / set / remove / keys / file / files` (لا `localStorage`).
### إنشاء الملفات والمجلدات داخل التطبيق
⚙️ ← 📁 الملفات والإضافات ← افتح الإضافة: زر **«➕ ملف جديد»** و**«📁 مجلد جديد»**. اكتب مساراً كاملاً بـ `/` فتُنشأ المجلدات المتداخلة تلقائياً (`src/bridge/AisaiAdapter.js`)، أو اكتب اسماً ينتهي بـ `/` ليُنشأ مجلداً فارغاً. المجلد يُفتح بالنقر عليه لتنشئ بداخله ملفات ومجلدات أخرى. يُنشر كل ذلك في `addons/<الاسم>/` عند المزامنة بنفس هيكله (والمجلد الفارغ يُحفظ بملف `.gitkeep`).

**رفع من الجهاز:** زر **«⬆️ رفع ملف أو مجلد»** بجانبهما: اختر «ملف أو عدة ملفات» أو «مجلد كامل»، فيدخل المجلد باسمه وبهيكله إلى المجلد المفتوح. يُرفع **كل شيء**: الكود والنصوص كما هي، والصور والأيقونات والخطوط والصوت وغيرها تُخزَّن ثنائياً (تُعرض الصورة في المستكشف ويُنزَّل أي ملف بزر «⬇ تنزيل»). داخل الإضافة اكتب `<img src="img/logo.png">` أو `url(img/bg.png)` في CSS فتعمل مباشرة؛ ولقراءة ملف بالكود استخدم `Alaisai.file('img/logo.png')` (رابط data: للثنائي). تُتجاهل `node_modules` و`.git`، وإن وُجد ملف بالاسم نفسه طُلب تأكيدك قبل استبداله، وما لا يمكن رفعه (أكبر من نحو 3MB أو يتجاوز حدود الإضافة) يُذكر سببه.
### إضافة إضافة جديدة
- **من المستودع:** أنشئ المجلد على GitHub ← يظهر في المتجر بشارة «جديد» عند مزامنة أي جهاز مضبوط، ولكل المستخدمين بعد النشر وبناء الكتالوج.
- **من التطبيق:** ⚙️ ← الملفات والإضافات ← «إضافة جديدة» أو «استيراد إضافة»؛ ومع المزامنة تُنشر ملفاتها في `addons/` تلقائياً.
### تعديل إضافة
عدّل ملفاتها في المستودع (أو في التطبيق)؛ تصل التعديلات للأجهزة المزامَنة تلقائياً، وإن تعدّلت في الطرفين يسألك التطبيق أي النسختين يعتمد. **ارفع `version` في manifest** ليتحدّث عند المستخدمين.
### حذف إضافة
في 🛍️ المتجر لكل إضافة مثبّتة زران مختلفان:
- **🗑 حذف:** يزيل أيقونتها من سطح المكتب فقط. تبقى في المتجر وملفاتها وبياناتها محفوظة، وتثبّتها متى شئت بزر «⬇ تثبيت».
- **⛔ حذف نهائي:** تظهر رسالة «هل أنت متأكد…؟» بخيارين: **تراجع** أو **نعم، احذف نهائياً**. عند «نعم»:
  - تُحذف الإضافة بملفاتها وبياناتها من هذا الجهاز، وتُخفى من متجره فلا تعود قابلة للتثبيت (زر «♻️ إظهار الإضافات المحذوفة» أسفل المتجر يعيدها إن غيّرت رأيك).
  - **إن كان على الجهاز مزامنة بصلاحية المالك** (وتطلب كلمة مرور الإدارة): يُحذف أيضاً من المستودع مجلدها `addons/<اسم>/` ومصدرها `catalog/src/<اسم>/` وحزمتها `catalog/addons/<اسم>.alaisai-addon.json`، وتُزال من فهرس المتجر `catalog/index.json`، فتختفي من متجر **كل** المستخدمين بعد نشر الموقع.
  - **إن لم تكن المزامنة مفعّلة على الجهاز** يبقى الحذف على هذا الجهاز فقط؛ لحذفها للجميع نفّذ الحذف من جهاز المزامنة، أو احذف مجلدها من GitHub وارفع.
  - لا يحذف أي ملف آخر في المستودع (قائمة بيضاء لمسارات الإضافة المحددة فقط).
- من GitHub: احذف المجلد. سيعرضها التطبيق «محذوفة من المستودع» مع «↻ إعادة نشر» أو «⛔ حذف نهائي»، **ولا يعيد رفعها بنفسه**.
- لإخفائها من المتجر العام: احذف مجلدها ثم ارفع (يُعاد بناء الكتالوج). من ثبّتها سابقاً تبقى عنده حتى يحذفها.

## 4) المزامنة مع GitHub
### الإعداد (مرة لكل جهاز)
1. مستودع على GitHub، وفرعه (`main`) موجود.
2. **Settings ← Developer settings ← Fine-grained tokens**: مستودع واحد فقط، صلاحية **Contents: Read and write**، ومدة محدودة.
3. ⚙️ ← المزامنة ← إعداد: المالك، المستودع، الفرع، الرمز، وعبارة تشفير (8+ أحرف).
### ما الذي يُزامَن
- ملف `alaisai-backup.json`: التطبيقات والملاحظات والبيانات، **مشفّر** بعبارتك.
- مجلد `addons/`: ملفات الإضافات **غير مشفّرة** (قابلة للقراءة والتعديل). أوقفها من لوحة المزامنة إن لم ترد.
- لا يُزامَن: كلمة المرور ومظهر الجهاز والرمز.
### مهم
- **عبارة التشفير لا تُستعاد** إن ضاعت. احفظها خارج المستودع.
- مستودع المزامنة الأفضل أن يكون **خاصاً**. وبما أن إضافات `addons/` تُنشر في المستودع نفسه، فالمستودع العام يعني أن إضافاتك ظاهرة للجميع (وهذا مطلوب إن أردتها في المتجر العام).
- إن اختلفت نسختان: يظهر «تعارض» ← اختر نسخة السحابة أو نسخة الجهاز (تُحفظ نسخة احتياطية قبل الاستبدال).
- رمز مشتبه به؟ ألغِه فوراً من GitHub (Settings ← Tokens ← Revoke) ثم أنشئ غيره.

## 5) الإدارة اليومية داخل التطبيق (⚙️)
| التبويب | ما فيه |
|---|---|
| 📱 التطبيقات | إضافة وتعديل وحذف وترتيب (أسهم أو سحب) التطبيقات |
| 📩 السجلات | البلاغات والأخطاء |
| ⚙️ النظام | المظهر، تغيير كلمة المرور، تصدير/استيراد نسخة (عادية أو مشفّرة)، إعادة ضبط المصنع (يمسح كل شيء)، «حول التطبيق وما الجديد» |
| 💾 النسخ | آخر 5 نسخ محلية تلقائية (كل 5 دقائق عند وجود تغييرات) مع استعادة وحذف وإنشاء نسخة يدوية |
| ☁️ المزامنة | رفع/سحب/اختبار/تفعيل التلقائية/فصل |
| 📁 الملفات والإضافات | مستكشف الإضافات والتجربة والتصدير |

- بعد 5 محاولات خاطئة لكلمة المرور يُقفل الدخول مؤقتاً. الجلسة بعد الدخول 5 دقائق.
- **قبل أي عملية كبيرة** (استيراد، سحب، إعادة ضبط) صدّر نسخة من ⚙️ النظام ← «تصدير نسخة» (أو المشفّرة).
- نسيت كلمة المرور: لا استعادة. الحل: إعادة ضبط المصنع (تفقد بيانات هذا الجهاز) ثم السحب من المزامنة أو استيراد نسخة.

## 6) التراجع عند حدوث مشكلة
| المشكلة | الحل |
|---|---|
| تحديث سيئ نُشر | في GitHub: افتح آخر commit ← Revert، أو `git revert <commit>` ثم push. ارفع رقم الإصدار ليصل التراجع للمستخدمين |
| الموقع لا يتحدث عندي | أغلق التطبيق وافتحه مرتين، أو امسح بيانات الموقع من إعدادات المتصفح. للجميع: ارفع `VERSION` في `sw.js` |
| إضافة تتعطل | احذفها (§3) أو عدّل ملفاتها؛ لا تؤثر على بقية النظام (معزولة) |
| بياناتي ضاعت | 💾 النسخ ← استعادة إحدى آخر النسخ، أو استورد آخر نسخة، أو ☁️ سحب من السحابة |
| فشل النشر (❌ في Actions) | افتح السجل: غالباً فشل اختبار أو خطأ في `manifest.json` لإضافة. أصلحه وارفع |
| المزامنة «خطأ» | اختبار الاتصال: الرمز منتهٍ؟ الصلاحية؟ اسم الفرع؟ |

## 7) الأمان: القواعد الذهبية
1. لا ترفع إلى المستودع: رمزاً، أو كلمة مرور، أو عبارة تشفير، أو ملف نسخة احتياطية غير مشفّر (`backup_*.json`).
2. رمز بصلاحية مستودع واحد وبمدة، وغيّره دورياً.
3. لا تفعّل إلا إضافات تثق بها: تعمل معزولة لكنها تعرض واجهة وتقرأ بياناتها الخاصة.
4. فعّل المصادقة الثنائية لحساب GitHub.
5. أبلغ عن الثغرات عبر `.well-known/security.txt` (تأكد من صحة رابطه).

## 8) الاختبارات والفحص قبل الرفع (اختياري لكنه مفيد)
```
node tools/build-catalog.mjs      # يبني الكتالوج
node tests/run.mjs                # 15 اختبار وحدة
python3 -m http.server 8765 &     # ثم:
python3 tests/e2e.py && python3 tests/e2e2.py && python3 tests/e2e3.py && python3 tests/audit.py
```
وبعد النشر: اختبر موقعك على https://pagespeed.web.dev ؛ المستهدف أداء/وصول/أفضل ممارسات/SEO كلها فوق 95.

## 9) كيف أطوّر أو أعدّل الكود بأمان
- غيّر شيئاً واحداً كل مرة، وشغّل الاختبارات، ثم ارفع.
- لا تغيّر أسماء ملفات `src/` دون تحديث `index.html` و`CORE` في `sw.js`.
- تغيير بنية البيانات (`Store`) يحتاج ترحيلاً في `src/storage.js` وإلا تضيع بيانات المستخدمين.
- أي ملف جديد في الصفحة: أضفه في `index.html` وفي قائمة `CORE` بـ`sw.js` ثم ارفع `VERSION`.

## 10) خارطة الطريق المقترحة
**جاهز الآن:** PWA كامل، إضافات حقيقية، متجر، مزامنة مشفّرة، نشر تلقائي، اختبارات.
**لم يُختبر بعد:** المزامنة مع GitHub الحقيقي (اختُبرت على نسخة وهمية). جرّبها وسجّل أي خلل.
| الأولوية | المهمة |
|---|---|
| 1 | تجربة المزامنة والإضافات على أجهزتك الفعلية وإصلاح ما يظهر |
| 2 | نطاق خاص (للمتاجر) ثم `node tools/set-site-url.mjs https://نطاقك/` |

| 4 | واجهة بالإنجليزية |
| 5 | مستودع خاص للنسخ المشفّرة منفصل عن مستودع الإضافات العام |
| 6 | تحسينات تصميم/إضافات جديدة حسب استخدامك |

## 11) أوامر Git السريعة
```
git status                  # ما الذي تغيّر
git add -A && git commit -m "وصف التغيير"
git push                    # نشر (إن كان الفرع main)
git log --oneline -10       # آخر التغييرات
git revert <commit>         # تراجع عن تغيير
```
